在线 Ridge、置信区间与 Conservative Benefit Gating

本节目标：从最小二乘推导项目在线算法，解释为什么“预测平均收益为正”仍不足以启用，以及如何处理探索、漂移和冷启动。

1. 问题建模

每次调度比较两个动作：upstream greedy 是固定上游原有的贪心计划，CacheFlow plan 是本项目生成的缓存感知候选计划。“贪心”表示只根据当前状态选眼前可行方案，不搜索很长的未来动作序列。

特征是描述当前状态的数字。特征向量 x 包括执行后端（CPU 或 CUDA）、批大小、decode/prefill token、chunk 数、活跃 sequence、KV 压力等；反馈 y 是实际迭代耗时，再加违反 SLO 或执行失败的惩罚。目标不是预测文字 token，而是预测系统动作成本。

为何分别为 backend/action 建模？CPU 与 CUDA 的成本尺度/瓶颈不同；upstream 与 CacheFlow 也产生不同数据分布。混成一个模型需要大量交互特征，少样本更容易错配。

2. 从最小二乘到 Ridge

普通最小二乘最小化 Σ(yᵢ−xᵢᵀθ)²。在线初期样本少、特征相关，XᵀX 可能不可逆或病态。加入 L2 正则：

minθ Σ(yᵢ−xᵢᵀθ)² + λ||θ||²
A=λI+Σxᵢxᵢᵀ, b=Σxᵢyᵢ, θ̂=A⁻¹b

在线更新只需 A←A+xxᵀ、b←b+xy。项目维度小，因此直接维护小矩阵并求解可接受；大维度才需要 Sherman–Morrison、Cholesky 更新或 SGD。

3. 置信半径

xᵀA⁻¹x 衡量当前上下文是否被历史数据覆盖：若方向上样本多，值小；若是新区域，值大。乘残差噪声估计和 β 得到半径：

prediction = xᵀθ̂
radius = β·σ̂·√(xᵀA⁻¹x)

只比较两个点预测 ĉ < û 很危险。项目使用保守条件：

CacheFlow upper cost + margin < upstream lower cost
ĉ+rc+m < max(0, û−ru)

成本越低越好，所以 CacheFlow 取悲观上界，upstream 取乐观下界。这等价于要求收益下界为正。注意 LinUCB 常为 reward 最大化使用乐观上界；本项目是 cost 最小化且重点是保守部署，方向不同。

4. 探索为什么必要，又为什么危险

若从不运行 CacheFlow，就没有它的反馈，模型永远无法学会它在何时更好；但探索可能损害真实 SLO。因此项目同时使用：

  • 结构安全区：多活跃 prefill、确有多 chunk 时才允许探索；
  • 最小 upstream 基线：先认识安全动作；
  • 探索间隔：不是每个 decision 都 probe；
  • 总预算：达到上限仍无正下界则 fail closed；
  • backend-local 风险：短生命周期 CUDA trace 零 probe，长驻 trace 单独验证探索。
关键区分：safe_exploration 是“为获取信息而承担受限风险”；positive_lower_bound 是“模型已有足够证据后的利用”。面试绝不能把探索次数说成学习成功次数。

5. 反馈、SLO penalty 与 drift

反馈成本可写成：

cost = elapsed + α·max(0, elapsed−target) + failure_penalty

SLO miss 会改变优化目标，但不一定是分布漂移：如果系统一直慢、模型也准确预测很慢，残差不大。项目只有在模型成熟后出现连续的大残差，或执行失败，才累计 drift streak；达到门槛后 reset 相应模型并进入 cooldown/upstream。

6. 53-wave 证据如何解释

最终 CUDA 单 PID：冷启动 0 次提前启用；稳定阶段 18 次探索、142 次正下界动作，覆盖 33 waves、最长连续 13 waves；终态收益 21.29ms 大于不确定性 8.82ms；切换 throughput-only 后 0 次 CacheFlow、3 次结构安全回退。

这比“某一时刻最大置信度”强，因为门禁同时要求连续 wave 和终态仍有置信；但它仍只证明当前模型/硬件/workload。分布切换由结构条件直接回退，并未触发统计 drift，这同样是正确结果。

手算练习：设 upstream 预测 20±3ms，CacheFlow 14±2ms，margin=1ms，判断是否启用。再把 CacheFlow 半径改成 6ms，解释为何平均预测仍更好却必须回退。

主动回忆

为什么一次 SLO miss 不应立刻 reset 模型？

解析drift 关心预测关系失效，即成熟模型的连续大残差；SLO miss 会加 penalty，但可能早已被模型预测。

7. 从 D1 到 D3：学习策略如何变成可控决策

D1 是全局线性 Ridge，它给每个动作估计成本和不确定性。它在当前回放中保持安全但不切换：这说明“没有错误启用”，不说明“已经学到收益”。D2 把 context length 按 512 token 分段，使不同长度区间能有不同参数；但校准 offset 为 7.446 ms，保守收益仍不足，所以仍不切换。

D3 新增风险约束的离线晋级规则。单次 replay 选择仍只比较分段 Ridge 的成本差上界：上界加 0.25 ms margin 小于 0 才偏离 H0；它不会在每次选择时扣减“剩余 harm budget”。完成整批留出 replay 后，策略还必须同时满足 harmful empirical rate 不超过 5%、累计 gain 大于累计 harm、P95 不劣于 H0 和 mean-regret delta 区间上界小于 0，才获准进入下一阶段 canary。

regreti = cost(choseni) − mina cost(a,i)
harmi = max(0, cost(choseni) − cost(H0,i))

v1.6 固定回放使用 60 条 fit、20 条 calibration、40 条 evaluation trace，共 600 个原始动作观测。H0 累计 regret 42.590 ms，D3 为 2.082 ms，下降 95.1%；D3 在 80 个 eligible decisions 中切换 24 次，仅 1 次 harmful。这里 harmful 定义为动作成本超过同 workload 的 H0 成本 3%，不是任意微小变慢。按 eligible 分母为 1.25%，按 switch 分母为 4.17%，两种比例回答不同问题，不能混用。

为什么仍不能说“线上有效”？回放中的各动作来自独立 fixed-mode 进程，动作与进程状态可能混杂；它也没有真的让 D3 在线改变生产请求。当前最强结论是：独立固定数据上，D3 比 H0 更接近 oracle，并且伤害受控，值得进入同进程 monitored canary。
口述练习：依次解释 D1 为什么不切换、D2 为什么仍不切换、D3 新增了什么状态；最后分别用 1/80 与 1/24 解释 harmful rate。
