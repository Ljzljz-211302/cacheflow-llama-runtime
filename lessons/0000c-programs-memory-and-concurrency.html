程序、内存、状态与“同时发生”

本节解释后续 COW、事务、竞态和所有权所需的最少操作系统/C++概念。

1. 程序、进程和线程

程序是磁盘上的代码；运行起来后成为进程，拥有自己的地址空间和资源。线程是进程内部的一条执行路线；多个线程共享进程内存，因此既能合作，也可能互相破坏数据。

服务通常有接收请求、执行计算、写响应等并发活动。并发不是“每件事物理上同时”，而是多项任务的执行时间交错；GPU 异步命令又增加一层并发。

2. 变量、地址、指针和所有权

内存可想成有编号的格子；编号是地址。C++ 指针保存地址。对象被释放后，旧指针仍保存数字，但指向内容已无效，再访问叫 Use-After-Free（释放后使用，UAF）。

所有权回答“谁负责保证对象活着、谁负责释放”。RAII 是 C++ 常用方式：资源绑定到对象生命周期，离开作用域自动清理。GPU 命令异步时，Host 对象退出作用域并不一定代表 GPU 不再使用底层 buffer。

3. 竞态与 happens-before

两个执行者访问同一数据，至少一个写入且没有确定顺序，结果依时机变化，这叫数据竞态。锁、原子操作、同一队列顺序或事件可以建立“甲完成在乙开始之前”的关系，称 happens-before。

错误：线程 A 释放 block ─┐ ├─ 顺序不确定 → GPU 可能读已释放内存 GPU stream 读取 ───┘ 正确：GPU 读取 → completion event → Host 等待/查询 → 释放 block

4. 状态机

状态机把对象可能处于的状态和允许的转换写清楚。例如一次推理迭代只能按下面顺序：

new → prepared → planned → executing → committed └────────→ aborted

它防止“未计划就执行”“执行一半却提交”等非法情况。测试不只验证成功，还要故意尝试非法转换。

5. 事务和原子性

事务把多步操作视作一个整体。原子性要求外界看到“全部完成”或“没有发生”，不能看到半成品。项目中计划 KV 复制、执行 CUDA copy、切换映射是多步操作，因此必须明确哪一步发布结果，失败时如何保持旧状态。

数据库常用日志，文件系统常用“写临时文件后 rename”。项目不照搬数据库实现，但借用同一原则：先准备完整新状态，再原子发布。

6. 引用计数与 COW

引用计数记录多少使用者指向同一对象。计数归零后才可能回收。写时复制（Copy-on-Write，COW）允许多人共享只读数据；某人要写时先复制一份，避免影响别人。

A ─┐ ├→ shared block，refcount=2 B ─┘ A 要写：copy → new block；A 改指向 new；old refcount=1；B 仍见 old
生活类比：用“多人共享云文档”和“另存为副本”解释 COW；再指出这个类比哪里不准确，例如真实程序的并发、失败和内存回收。
