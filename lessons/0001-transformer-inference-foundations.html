Lesson 01 · 模型主课 · 55 min

Transformer 怎样利用历史文字生成下一个 token

00A 已把 token 定义为模型处理的文字片段。本节从“一个 token 怎样参考历史 token”开始，逐步得到 Attention、Prefill、Decode 和 KV Cache，不要求预先认识这些词。

0. Transformer 是什么

神经网络可以先理解为许多带参数的数学变换连接起来。Transformer是其中一种结构，它的关键能力是让序列中每个位置根据需要读取其他位置的信息。这个“决定应该关注哪些位置并加权汇总”的步骤叫 Attention（注意力）。

token 的整数编号先被查表变成一串实数，叫向量表示（embedding）。经过网络层后，每个位置拥有一个包含上下文信息的向量，常称 hidden state（隐藏状态）。这里的“隐藏”只表示它是网络内部数值，不表示加密。

Q、K、V 的日常直觉

  • Query（Q，查询）：当前位置想找什么信息；
  • Key（K，键）：历史位置提供什么匹配标签；
  • Value（V，值）：匹配后真正取回什么信息。

Q、K、V 都不是文字，而是由 hidden state 乘不同参数矩阵得到的向量。Q 与各 K 做点积得到相似分数，softmax 把分数变成总和为 1 的权重，再对 V 加权求和。

1. 自回归模型到底在算什么

自回归表示“用已经出现的 token 预测下一个 token”。概率公式 P(x₁…xₙ)=∏P(xₜ|x<t) 的白话是：整段文本出现的可能性，可以拆成每一步“在此前内容条件下，下一个 token 出现的可能性”的乘积。

生成第 t 个 token 时只能使用已有前缀。后文把“模型执行一次、为活跃请求推进一步”称为一次 forward（前向计算）。GPU 能并行一次 forward 内的大量矩阵运算，也能同时处理多个请求，但不能提前知道尚未生成的未来 token。

数学写法如下；先读变量意义，再记公式：

Q=XWQ, K=XWK, V=XWV
Attention(Q,K,V)=softmax(QKᵀ/√dk)V

除以 √dk 是为了避免维度增大时点积方差过大，使 softmax 过早饱和。causal mask 把未来位置 score 设为负无穷，保证位置 t 不能偷看未来。

2. Prefill 和 Decode 是什么

一次请求先有用户输入，再逐个产生回答。系统把这两个阶段分别命名：

Prefill（输入预处理）Decode（逐步生成）
输入一次处理用户输入 prompt（提示文本）的许多 token每个活跃 sequence（生成序列）通常增加 1 token
并行性token 维度高，可形成大矩阵跨时间串行，单轮矩阵较“瘦”
常见瓶颈计算量、长迭代阻塞历史数据读取、显存带宽、启动/批处理效率
主要指标TTFT：从请求到首个输出 token 的时间TPOT：首 token 后每个输出 token 的平均间隔

如果一个 2000-token prefill 和正在 decode 的会话放进同一轮，GPU 利用率可能更高，但 decode 用户会等待一整个长迭代。这就是吞吐—延迟冲突，也是 chunked prefill 的动机。

3. KV Cache 推导

Cache（缓存）是保存之后还会复用的计算结果。生成新 token 时，新 Q 仍需和所有历史 K/V 做 attention，但历史 token 的 K/V 已经算过且不会变化。KV Cache就是把每层历史 K/V 保存在显存中，避免下一步重新计算整个历史。

Decoder-only指只保留 Transformer 生成侧结构的语言模型；GQA（Grouped-Query Attention）让多组 Q 共享较少的 K/V heads（注意力头），以减少 KV 容量。粗略容量为：

bytes = layers × tokens × 2(K,V) × kv_heads × head_dim × dtype_bytes × sequences

layers 是网络层数；kv_heads 是 K/V 注意力头数；head_dim 是每个头的向量维度；dtype_bytes 是每个数字占多少字节；sequences 是同时保存的生成序列数。公式中的 2 表示 K 与 V。

例：24 层、4096 token、2 个 KV heads、head_dim=64、FP16、单 sequence：

24 × 4096 × 2 × 2 × 64 × 2 = 50,331,648 bytes ≈ 48 MiB

FP16表示每个浮点数使用 16 bit，也就是 2 bytes；MiB是按 1024×1024 bytes 计算的内存单位。

注意：不能直接用参数量推 KV；KV 由层数、上下文、KV head 几何和精度决定。GQA/MQA 通过减少 KV heads 显著降低容量，但 query heads 不一定减少。

项目连接：容量公式进入 server-kv-capacity-planner.*；Block runtime 管理的是这些随 token 增长的 KV，而不是模型权重。模型权重常驻和 KV 动态容量必须分开算。

4. 为什么小模型结果不能直接外推大模型

模型变大后，权重读取、算力占用、KV 几何、batch 饱和点、kernel 数量都会改变。0.5B 在 RTX 4050 上看到的“某策略有害”，可以证明控制器需要门控，却不能证明 7B/A100 上方向相同。面试时应说“机制可迁移，数值结论需重跑”。

白板练习：给定 layers=32、tokens=8192、kv_heads=8、head_dim=128、BF16（同样每个数 2 bytes）、同时 4 个生成序列，独立计算 KV 容量；再说明把 kv_heads 从 8 降到 2 后容量变成原来的几分之一。分块问题留到 Lesson 03。

主动回忆

为什么 decode 有 KV cache 后仍会随上下文变慢？

解析KV cache 省掉历史 K/V 的投影重算，但没有省掉新 query 对历史 K/V 的读取和 attention。
