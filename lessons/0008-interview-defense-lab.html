Lesson 08 · 综合演练 · 90 min

把项目讲成“可验证的个人研究工作”

本节目标：形成 30 秒、3 分钟和 15 分钟三种叙事；用追问清单检验自己是否真正掌握，而非背稿。

1. 30 秒版本

我基于固定版本 llama.cpp，在真实 llama-server → llama_decode → KV → CUDA 热路径上实现了 CacheFlow Runtime。核心工作包括 iteration-level Engine、cache-aware scheduler、Paged Prefix KV/COW、Host/File/CUDA swap、自研 KV kernels，以及用在线 Ridge 置信下界控制 CacheFlow 是否启用。我用真实模型、Compute Sanitizer、故障注入、多 trial A/B 和 CUDA→Engine→TTFT 因果链验证；同时保留负结果，不声称所有 CUDA workload 都提升。

2. 三分钟结构

  1. 问题：LLM serving 的 prefill/decode 干扰、KV 动态内存和固定策略跨 backend 失效。
  2. 架构：把循环拆成 prepare/plan/execute/commit；Scheduler、KV manager、runtime adapter 通过窄接口协作。
  3. 算法：block table/refcount/COW；chunk/spec 控制；backend-local online Ridge + confidence gating。
  4. CUDA：真实 tensor gather/scatter/COW、direct/staging 分流、stream/event 生命周期和 sanitizer。
  5. 证据：53-wave 收敛；paired CUDA 因果链；严格 full gate。
  6. 边界：单机 0.5B/4050、无 Nsight 全 census、mixed CUDA 收益不稳定。

3. 个人贡献边界

上游提供 GGUF、GGML 图与通用算子、模型实现、sampling、HTTP 基础设施；个人差异以固定上游 patch 为准：59 files、+8445/−99 C/C++/CUDA，外层另有实验与报告。正确说法是“重构并扩展固定上游的 serving 热路径”，不是“重写了 llama.cpp”。

4. 高频追问与答题骨架

追问答案必须包含
为什么这是 AI Infra？真实 serving 热路径、KV/CUDA/调度/性能—正确性权衡，不是 Python API 包装。
为什么不用 vLLM？学习目标是深入 llama.cpp 单机 C++/CUDA；借鉴 paging 思想但自行接入固定上游；不做无意义优劣宣称。
COW 怎么保证正确？refcount 不变量、allocate-copy-remap-dec 顺序、异步 event、失败回滚、测试。
Ridge 为什么合理？小维度、在线闭式更新、正则稳定少样本、置信半径可解释；非线性强时存在欠拟合边界。
为什么需要探索？反事实反馈不可同时观测；无探索无法学另一动作；结构区间/频率/预算/回退限制风险。
为什么短 CUDA 不探索？fresh-process 风险预算；always 已知有害，单 probe 可破坏 3% SLO；长驻实验独立证明学习。
CUDA 指标改善为何 TTFT 变差？局部 copy/Event 与全局 batch/排队不同层；chunk 更多；因果链显示系统结果，需 Nsight 继续定位。
怎样证明不是偶然？fresh process、paired Latin、多 trial、固定门槛、原始 evidence；仍承认样本/硬件限制。
最大技术债？动作空间仍主要是 prefill plan；未联合 slot/KV admission/swap/spec；缺多 GPU 与 Nsight。

5. 现场演示顺序

  1. 打开 server-inference-engine.*，指出状态所有权和事务阶段。
  2. 运行/展示 test-kv-block-manager：prefix share → partial-tail COW → refcount 守恒。
  3. 打开 llama-kv-cache-paged.cu：解释线程索引、mapping、direct/staging 选择。
  4. 展示 long_lived_benefit_cuda_summary.json：冷启动、持续利用、终态置信、shift 回退。
  5. 展示 cuda_causal_profile_summary.json 与 evidence：讲负结果和证据边界。

6. 15 道闭卷自测

  1. 推导 GQA KV bytes 公式。
  2. prefill 为什么更 compute-heavy，decode 为什么更 bandwidth-sensitive？
  3. iteration-level scheduling 解决什么，不解决什么？
  4. Request、Sequence、Slot 为什么分离？
  5. 写出 Block Table/refcount 不变量。
  6. 画 partial-tail COW 的成功和复制失败路径。
  7. 不同 CUDA stream 如何建立 happens-before？
  8. Event 时间和端到端 TTFT 有何区别？
  9. Ridge 的 λ 如何影响 bias/variance？
  10. 解释 xᵀA⁻¹x。
  11. 为何 cost 最小化用悲观 CacheFlow 与乐观 upstream？
  12. SLO miss 与 drift 有何区别？
  13. chunk size 太大/太小的失败模式是什么？
  14. 本项目 speculation 与论文双模型算法有何差异？
  15. 最终 CUDA 因果结果支持和不支持哪些结论？
评分规则：每题 0=不会；1=能背定义；2=能推导；3=能连接代码/数据并说明边界。总分 45，达到 36 且任何题不为 0，才进入模拟面试。错题隔 1 天、3 天、7 天重新闭卷回答。

答辩判断

面试官问“项目是不是 vLLM 的复刻”，最佳第一句是什么？

解析承认思想来源，马上指出代码边界、实现差异与可验证证据，最可信。

7. 面试禁区

  • 不说“CUDA 加速了整体服务”；本轮 causal intervention 的 TTFT 反而恶化。
  • 不把 phase-duration SVG 称为 sampled-stack flame graph。
  • 不把 deterministic replay、safe exploration 或单次峰值称为线上收敛。
  • 不说“通过 sanitizer 所以没有 bug”；它只覆盖特定错误类别和测试输入。
  • 不说“比 vLLM 快”；没有同硬件同模型同 workload 的可信对照。
完成标准：录制一次 3 分钟讲解；随机抽 5 道自测；现场打开 3 个源码文件定位；对一个负结果给出至少两个竞争性解释和下一步实验。
