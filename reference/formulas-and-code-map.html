核心公式与代码地图

面试前 10 分钟复习：每个公式必须能说明变量、假设、复杂度，以及它如何进入当前实现。

1. Attention 与 KV

Attention(Q,K,V) = softmax(QKᵀ / √dk)V

Prefill 长度为 n 时，标准 attention score 的计算/存储具有二次项；decode 只产生一个新 query，但需读取历史 n 个 K/V。KV cache 避免为历史 token 重算 K/V。

KV bytes ≈ L × T × 2 × Hkv × Dhead × bytes(dtype) × active sequences

2 表示 K 与 V；若使用 GQA，Hkv < Hq。本项目容量规划必须使用模型几何，而不是写死“每 token 若干 KB”。

2. Block 与 COW 不变量

physical(block) = block_table[sequence][logical_block]
∀p: refcount[p] = |{(s,l) : block_table[s][l] = p}|

写共享块前必须满足 refcount==1；否则分配新块、复制有效 token、原子性地切换写者映射，再递减旧块引用。失败时应保持旧映射有效。

3. 调度分数

score = cache_reuse_gain − prefill_cost − eviction_penalty + aging_bonus − SLO_risk

项目不是声称该线性式具有普适最优性，而是把可解释因素放进一个可测试、可回退的策略 seam。真正提交的 IterationPlan 必须冻结，不能在 execute 阶段悄悄改变。

4. Ridge 与置信门控

A = λI + Σxᵢxᵢᵀ,　b = Σxᵢyᵢ,　θ̂ = A⁻¹b
ŷ(x)=xᵀθ̂,　radius(x)=β·σ̂·√(xᵀA⁻¹x)
启用 CacheFlow iff ĉ + rc + margin < max(0, û − ru)

这是“CacheFlow 悲观成本仍小于 upstream 乐观成本”。项目分别维护 backend/action 模型；探索有间隔和预算，drift 用成熟模型的连续大残差触发。

5. 服务指标

TTFT = t(first non-empty token) − t(request accepted)
TPOT ≈ [t(last token) − t(first token)] / max(output_tokens−1,1)
throughput = Σ completion_tokens / wall_time

P95 先对每个 trial 内请求求分位，再跨 fresh-process 汇总；不能拿一次最快值代表收益，也不能用不同 trial 的两个独立中位数冒充 paired ratio。

6. 一次请求的代码路径

HTTP/SSE request → tools/server/server-context.cpp → server_inference_engine::run_iteration prepare → plan → execute → commit/abort → server_inference_scheduler (slot / prefill / decode) → server_benefit_policy (upstream vs CacheFlow shadow plan) → server_kv_block_manager / capacity_planner / swap_store → server_runtime_adapter → llama_decode → llama-kv-cache-paged.cu / server-kv-block-cuda.cu → CUDA stream + event → metrics / Engine trace / SSE token
