推免面试追问题库

先闭卷回答，再展开要点。优秀答案不只给定义，还要连接项目代码、实验与边界；遇到新名词先给定义，再讲机制、数据和适用条件。

A. 模型与推理

1. 为什么 Attention 要除以 √dₖ？

若 Q/K 各维近似独立、方差为 1，点积方差随 dₖ 增长。尺度过大会让 softmax 接近 one-hot、梯度区间变差。除以 √dₖ 把点积分布尺度稳定在相近范围。项目连接：它解释模型图，但不是本项目个人实现。

2. KV cache 节省了什么，没节省什么？

节省历史 token 在每层的 K/V 投影重算；没有省掉新 query 对历史 K/V 的读取和 attention，也没有消除跨生成 token 的自回归串行依赖。上下文越长，decode 仍可能更慢。

3. Prefill 与 decode 的 roofline 特征为何不同？

Prefill 有较大 token 维度，更容易形成高算术强度矩阵乘；decode 每个 sequence 每步仅一个新 token，算子更瘦、权重/KV 读取占比高，常更受带宽和 launch/batch 效率限制。具体结论依模型、batch 和 GPU，需 profiling。

4. GQA 如何改变 KV 容量？

query heads 多个一组共享较少的 KV heads。KV bytes 使用 Hkv 而不是 Hq，因此容量与 Hkv 线性相关。Attention 输出仍对应 query heads，不能把 Hq/Hkv 混用。

5. 量化权重为何不等于量化 KV？

权重量化改变模型常驻参数的存储/计算；KV dtype 由运行时缓存配置决定。二者有不同精度和带宽影响，计算 VRAM 时应分项。

B. Engine、调度与 KV

6. prepare/plan/execute/commit 比一个大循环好在哪里？

它明确状态所有权和副作用边界：plan 可构造/比较 shadow plan，execute 只消费冻结计划，commit 才发布状态。失败可 abort，避免一半 slot/KV 已更新、一半仍旧状态。代价是接口和事务 bookkeeping。

7. iteration-level scheduling 会不会让吞吐下降？

可能。更频繁调度和过小 batch 会增加开销；价值是允许动态 batching、减少头阻塞并改善延迟。需要在吞吐与 TTFT/TPOT 约束下选择，而非认为粒度越细越好。

8. Cache-aware 调度怎样导致饥饿？

若复用收益长期主导分数，新 prefix/低命中请求可能一直输。项目加入 aging/SLO/eviction 等因素；测试应构造热门 cache 请求持续到达而老请求仍最终被选中的序列。

9. Block size 为什么不是越小越好？

小块降低尾部内部碎片，提升共享/COW 粒度；同时增加 Block Table、refcount、mapping、kernel/拷贝次数和 launch 开销。默认 16 是当前实验折中，换模型/硬件需重测。

10. COW 的线性化点在哪里？

可把“写者 Block Table 从旧块切到已完整复制的新块”视为发布/线性化点。在此之前其他读者仍见旧块；之后写者独占新块。CUDA copy 完成必须 happens-before 该发布。

11. refcount 归零为什么还不一定能立刻释放 GPU 块？

Host 映射已无引用，不代表先前异步 kernel 已结束。还需 stream 同序或 completion event/fence；否则会发生异步 UAF，甚至块被重新分配后形成 ABA。

12. Swap 与 recompute 怎么选？

比较 KV 搬运/存储/恢复成本与重新 prefill 计算成本，还要考虑 Host/磁盘容量、SLO、prefix 可复用性和失败复杂度。短 prefix 可能重算更便宜，长 prefix 或计算昂贵模型更偏 swap。

C. CUDA 与体系结构

13. 为什么自研 gather/scatter kernel 可能输给多次 memcpy？

通用 mapping 带索引读取、边界、launch 和可能的不连续访问；无重叠的连续块复制可被 CUDA memcpy 路径高效处理。kernel 只在重叠/重复映射需要 snapshot 语义或能有效融合时有优势。

14. Coalescing 的本质是什么？

warp 中线程访问可合并为尽量少的内存事务。关键不是“地址必须完全连续”这一口号，而是访问落入多少内存 segment、对齐与数据宽度。mapping 随机会破坏合并并增加事务。

15. Event 和 cudaDeviceSynchronize 的取舍？

device synchronize 等待设备所有先前工作，简单但扩大同步范围；event 可标记特定 stream 位置，用于精确依赖和计时，让无关 stream 继续。Event 本身也有管理成本，且必须关联正确 device/stream。

16. pinned memory 为什么重要，又有什么代价？

page-locked Host memory 支持稳定 DMA/异步传输与 copy-compute overlap；但锁页减少 OS 可分页内存，分配较贵，过量会伤害系统。项目对 swap buffer 应有预算和复用。

17. memcheck/racecheck 全绿后还要测什么？

Host 数据竞争、跨 stream 生命周期、算法语义、文件崩溃一致性、OOM、性能回归、模型兼容和输出质量。sanitizer 是必要门槛，不是完整正确性证明。

D. 在线学习与控制

18. Ridge 正则 λ 增大有什么影响？

参数更收缩，方差/病态敏感性下降，但 bias 增加，可能低估真实特征效应。在线早期通常需要稳定性；数据变多后固定 λ 相对数据项影响减弱。

19. 为什么维护 action-specific model？

bandit 只观察所选动作的反馈；两个动作的成本函数可能不同。分模型便于学习各自参数与不确定性，但样本被拆分、冷启动更慢，因此需要受限探索。

20. 项目策略与标准 LinUCB 有何差异？

LinUCB 通常最大化 reward 的乐观上界以探索；项目最小化系统 cost，并要求 CacheFlow 悲观上界仍低于 upstream 乐观下界，偏向安全部署。同时另设稀疏探索预算，不把纯 UCB 乐观动作直接放入生产。

21. 如何识别 distribution shift？

用成熟模型的预测残差，而不是单次原始 latency。连续残差超过预测尺度的倍数或 execution failure 才触发 reset/cooldown；结构不安全状态可直接 fallback，无需等待统计 drift。

22. 为什么终态置信门槛重要？

只要求历史曾出现连续 positive waves，模型可能后来失效仍通过。终态 `predicted_benefit > uncertainty` 防止挑选全程最大值的选择偏差，证明实验结束时仍保持置信。

E. 实验、贡献与边界

23. 为什么需要 paired Latin，而非各跑若干次取中位？

配对让同一 trial 的共同环境被差值抵消；Latin 轮换策略顺序，降低热机/温度/时间趋势混杂。必须先算 pair effect，再汇总；仍需足够样本和原始数据。

24. 最终 CUDA 因果结果的最强结论是什么？

强制策略确实改变决策、prefill 分块和 CUDA KV 中介，并伴随 material Engine/TTFT 恶化；局部 copy/Event 下降未转化为端到端改善。不能据此断言具体 SM/occupancy 根因，也不能外推其他模型/GPU。

25. 如何证明个人贡献不是原仓库？

固定上游 commit，以可逆 patch 统计 59 files、+8445/−99 C/C++/CUDA；逐模块展示新 Engine、Scheduler、KV/CUDA、在线策略持久化、控制器、测试和实验。明确上游保留 GGML/GGUF/model graph/sampling/HTTP，不声称重写 llama.cpp。

F. D1 / D2 / D3 学习策略

26. D1 是什么，为什么没有切换？

D1 是对每个动作建立全局线性 Ridge 成本模型，并用不确定性下的保守收益门决定是否偏离 H0。它没有切换，表示所有候选的可信收益都未覆盖 margin；安全门生效，但全局线性关系不足以找到局部获益区，不应包装成“学习成功”。

27. D2 的 piecewise 模型解决什么？

Piecewise 表示把输入空间分段后分别拟合。D2 以 512-token context 区间建模，让不同长度不必共享同一斜率；但 v1.5 calibration offset 为 7.446 ms，保守估计仍不允许切换，说明分段表达力提高不等于校准已可靠。

28. D3 的风险门禁与安全 margin 有什么区别？

Margin 是单次 replay 选择必须跨过的固定安全间隔：成本差上界加 0.25 ms 仍小于 0 才切换。风险门禁在整批留出 replay 完成后验收 harmful rate、gain/harm、P95 和 CI；当前实现没有会逐次扣减的在线 harm budget。若 canary 要增加累计停止预算，那是下一阶段的新状态。

29. Regret 是什么，为什么不用普通准确率？

Regret 是所选动作成本减去同一 workload 可行动作中的最低成本。分类准确率把差 0.01 ms 与差 10 ms 的错误同等计数，而 regret 按工程代价加权，更符合调度目标。

30. D3 最新结果如何完整口述？

120 traces=60 fit+20 calibration+40 evaluation，共 600 observations。评估中 H0/D3 累计 regret 为 42.590/2.082 ms，下降 95.1%；P95 为 3.169/0 ms。D3 在 80 个 eligible decisions 中切换 24 次，1 次 harmful，总 gain/harm 为 41.480/0.972 ms。

31. 为什么 harmful rate 有 1.25% 和 4.17% 两个值？

协议把成本超过同 workload 的 H0 成本 3% 定义为 harmful，不把微小抖动算成伤害。1/80=1.25% 以全部 eligible decisions 为分母，回答所有决策机会中多常有害；1/24=4.17% 以实际 switches 为分母，回答一旦偏离 H0 后多常有害。报告比例必须同时给事件数和分母。

32. 材料中的 5% 能否叫 95% 安全保证？

不能。5% 是实验前注册的 harmful-rate 晋级阈值，不是观测比例；实际观测是 1/80=1.25% 或 1/24=4.17%。该阈值不是总体 harmful rate 的 95% 置信上界，也不是 SLO。要做概率上界需预先确定二项事件、分母和区间方法，并满足抽样假设。

33. D3 的 trace-cluster CI 表示什么？

以完整 trace 为 cluster 做 bootstrap，估计 D3 与 H0 的 mean-regret delta；95% CI 为 [−0.7232,−0.3069] ms，负值表示当前固定回放中 D3 regret 更低。它不是 95% 请求延迟区间，也不是线上因果效应。

34. 为什么训练/校准/评估要分开？

训练集拟合参数，校准集选择 offset、margin 或阈值，评估集只做最终一次无偏比较。若反复看评估结果调阈值，评估集就泄漏成训练信息，漂亮数字会过拟合这批 traces。

35. H0 fallback 为什么是算法的一部分？

H0 是证据不足、能力不支持、预算耗尽或运行异常时的确定安全动作。生产策略不只定义“何时优化”，还必须定义“何时不优化”和如何恢复；fail closed 是决策规则的一部分，不是异常补丁。

G. 实验设计、统计与因果边界

36. Formal Trial Pair 的最低条件是什么？

同一实验单位上的处理/对照必须由预注册协议配成一对，并绑定输入、顺序、进程、请求、指标和原始证据；先算 pair 内效应再汇总。仅按相同标签拼两行不自动成为 formal pair。

37. Matched-workload replay 与线上 A/B 的差别？

Replay 在已采集的各动作 observation 上离线模拟选择；线上 A/B 让策略真实决定生产或 canary 请求并随机分配。Replay 可比较规则但不捕获策略改变后续队列/缓存状态的反馈。

38. action×process confounding 是什么？

若动作 A 总由进程 1 执行、动作 B 总由进程 2 执行，进程热身、内存布局或 GPU 状态与动作共同变化，观察差无法唯一归因于动作。当前 D3 正有此边界，需同进程交替/随机执行缓解。

39. 为什么按 trace cluster bootstrap？

同一 trace 内多个动作 observation 共享请求结构，彼此相关。逐行重采样会伪造独立样本并低估不确定性；按完整 trace 重采样保留组内相关关系。

40. P95 为 0 是否意味着没有任何伤害？

不意味着。P95 regret 为 0 表示至少 95% 经验分布不超过 0；仍可能有少量正 regret，D3 就有 1 次 harmful。必须同时看 max、事件数、累计 harm 和原始行。

41. 置信区间不跨 0 能否证明因果？

不能。它只说明在估计器与抽样假设下方向较稳定；若存在混杂、选择偏差或协议不是干预实验，再窄的区间也只是精确估计了有偏对象。

42. 什么是 profiler effect？

Profiler 会插桩、收集事件和改变同步/调度，使被测程序本身变慢或时序改变。主性能结果应来自 no-profiler trials，NSYS/NCU replay 用于解释机制，两者不能混成一个 latency 估计。

43. 为什么 Engine execute 与 TTFT 可能反向？

execute 是阶段累计时间，TTFT 还包含请求到达、队列、分块轮次、batch 竞争和 socket 首字节。一个阶段总量降低不保证某请求关键路径缩短，尤其当调度改变了等待结构。

44. 怎样设计 same-process monitored canary？

在同一长驻进程中对符合条件的请求随机或按平衡序列选择 H0/D3，限制流量与 harm budget，记录选择概率、上下文、动作、队列/KV 状态和结果；达到停止阈值立即回退，并按请求/会话 cluster 分析。

45. 多重比较为什么危险？

尝试大量指标、切片和阈值后只报告最好结果，即使无真实效应也容易出现偶然亮点。应预注册主指标和 promotion gate，其他结果标为探索性，并保留完整数据。

H. Paged Attention 与算子细节

46. Paged Attention 的“页”是什么？

它是 KV cache 的固定 token block，不是操作系统虚拟内存页。逻辑 token 通过 block table 找到物理 KV block，从而允许非连续分配、共享和 COW。

47. online softmax 为什么只需有限状态？

扫描分块 logits 时维护当前最大值 m、按新最大值重缩放后的指数和 l、以及同样重缩放的加权 value 累积 o。每合并一块都先把旧状态乘 exp(m_old−m_new)，因此无需保存全部 logits，且数值稳定。

48. causal mask 与最后一页 tail 如何处理？

每个 query 只能访问不晚于当前位置的 key；最后物理页可能未填满，只允许 context length 以内的 lane 参与 max、sum 与 value 累积。越界值即使内存可读也必须被 mask。

49. K1、K2、K3 分别是什么？

K1 为一个 CTA 负责一个 query head，结构简单、易验证；K2 利用 GQA 中多个 query heads 共享 KV head，协同加载减少重复读取；K3 把超长 KV 维度切给多个 CTA 后合并 partial softmax，提高并行度但增加合并开销。

50. 为什么真实 Qwen2.5-0.5B 不是 D128？

当前 0.5B 几何是 24 层、14 query heads、2 KV heads、head dimension 64，GQA ratio 7。D128 的 model-faithful 例子是 Qwen2.5-7B 的 28Q/4KV/D128；把合成 D128 benchmark 描述成 0.5B 会造成模型事实错误。

51. FlashInfer 为什么不是当前 ratio-7 的直接 oracle？

固定依赖版本的 CUDA-core 专门化只实例化若干 GQA ratio，未含 7。可以用数学 CPU/框架 reference 做正确性 oracle，或新增受验证的 ratio-7 specialization；不能因库名相同就宣称 drop-in 对照。

52. 为什么正确 kernel 仍可能更慢？

page-table 寻址、低 occupancy、重复 KV 读取、同步和 launch 固定成本可能超过省下的 remap；短 context 并行度不足，长 context 又可能带宽受限。正确性是上线必要条件，promotion 还需分 regime 性能门。

53. NCU 失败时还能声称什么？

若因权限得到 ERR_NVGPUCTRPERM，就不能声称 occupancy、DRAM throughput 或 cache hit 根因。仍可报告 no-profiler latency 与 NSYS 可观察的 launch/copy/timeline，并把硬件计数器解释标为待验证假设。

I. 生产可靠性与可观测性

54. 为什么 capability gate 必须在评分前？

不支持的动作没有合法成本语义，让模型给它打高分后再失败会污染反馈并伤害 SLO。应先按模型几何、backend、内存、alignment 和资源预算构造 feasible set，再只在其中比较。

55. 事务式 Engine 如何处理部分失败？

prepare/plan 阶段不发布外部状态；execute 产生带 completion 的结果；commit 只有在全部不变量满足后更新 slot/block 映射。失败走 abort，释放 reservation/lease 并保留旧映射，避免半提交。

56. 指标为什么区分 counter、gauge、histogram？

Counter 表示累计事件且只增，Gauge 表示当前状态可升降，Histogram 保存分桶计数/总数/总和。对 gauge 做 phase 差值或把最后值当事件次数都会产生错误结论。

57. 如何验证证据没有被手工改摘要？

manifest 绑定原始树和派生文件 hash；validator 从 CSV、evidence、trace/SQLite 独立重算主结果，并比较 trial/request/PID/计数器与 causal links。仅校验 JSON 格式或 passed=true 不够。

58. OOM 时为何不能盲目 swap？

swap 需要 pinned host/file 容量、传输时间和可恢复句柄；传输可能比重算更慢并阻塞关键 stream。策略应检查资源与 SLO，必要时 preempt/recompute/fallback，所有失败都要回滚 reservation。

59. 用户取消怎样传播到 GPU 工作？

HTTP/SSE 断开应标记 request cancelled，调度器停止新增工作；已提交 kernel 通常不能任意撤销，需等待 event 后安全释放 lease。取消语义必须避免响应已断却持续占槽和 KV。

60. 线上 drift 触发后怎么做？

停止非基线动作、进入 cooldown、保存触发上下文和模型版本，按 action/backend 重置或降权统计，再用受限 canary 恢复。单次慢请求不足以判 drift，应看成熟模型的连续标准化残差或执行失败。

J. 架构、贡献与开放追问

61. 为什么这是 AI Infra 而不是普通 Agent 项目？

核心改动位于模型 serving 热路径：iteration scheduler、KV 内存生命周期、GPU kernel/stream/event、Paged Attention、在线动作策略与端到端观测。它优化“模型怎样被执行”，而不是只调用模型 API 编排工具。

62. 最大创新点如何只用一句话表达？

把 KV 内存动作、分页算子和在线学习统一进一个 evidence-gated runtime：先证明可行，再预测成本、限制风险，最后用可重算证据决定是否 promotion。

63. 如果面试官说“都是已有论文思想”怎么办？

承认 paging、continuous batching、Ridge 等思想来源，再说明个人问题在于把它们接入固定 llama.cpp 热路径、定义不变量和失败回退、自研受限算子、建立统一动作 cost boundary，并产出可篡改检测的实验制品。科研贡献可以是新系统组合与实证发现，不等于宣称原创基础理论。

64. 为什么负结果也能体现能力？

负结果只有在假设、对照、阈值、原始数据和后续决策完整时才有价值。Paged K1 中长 context 更慢促使方向转向 GQA reuse；promotion gate 阻止不成熟快路径默认上线，这体现系统判断而非“失败美化”。
